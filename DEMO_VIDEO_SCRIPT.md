# Vouch demo video script

Recommended length: about 4 minutes 30 seconds. Open http://127.0.0.1:8080/. This is a recording script, not a claim that a video has already been recorded.

## Why these screens, based on the attached brief

I read all four pages of `CalHacks_Hyphenate_Track (1).pdf`. The brief's four judging questions are whether the system is realistic, whether the team would hire it, whether the approach is new, and whether there is a memorable catch or recovery. Page 1 calls out conflicting sources, time, working with others, limited authority and traceable decisions. Page 3 specifically asks the video to open with the moment, and asks for a real live demo, a seat line and evidence that distinguishes real execution from simulated company data.

That is why the sequence below starts with the late bill's financial consequence, then shows the workflow and its controls. It does not start with a dashboard tour. P11 demonstrates the catch, P01 shows why attendee-level details matter, P03 shows history changing today's decision, P10 shows asking a person and following the answer, and the custom-event form shows that Vouch is not limited to a rehearsed case list. The audit record connects these outcomes to evidence. Ten-year Books coverage is shown briefly, with empty years labeled honestly.

## Before recording

1. Run `python -m vouch preflight`; require GREEN. Start the app with `python -m vouch api --host 127.0.0.1 --port 8080` if the prepared server is not already running. Use the configured Jev provider, not Scripted demo.
2. Run P11 once and frame its Case File before pressing Record. Then actually trigger P11 again for the live-execution section. Re-record if a model call fails; do not present a scripted or failed run as live success.
3. In each scenario, approvals, entries and ledgers belong to the current isolated company snapshot. Capture them before starting the next scenario. There is no UI authentication deployment: reviewer identities and colleagues are simulated. Do not claim production identity security or a real email/payroll/tax-authority integration.
4. Keep the terminal test summary or verified results JSON ready for the closing evidence shot. Use the latest successful report's model, date and repetition count. Supplemental cases are agent-authored regressions, not an independent blind benchmark. No claim is made about the owner's new holdout.
5. Keep `.env`, provider dashboards, keys, private holdout files and raw server logs out of the recording. The ten-year window is coverage, not a claim that ten years of transactions exist.

If you only have two minutes: keep the opening P11 catch, live trigger, human approvals, P10 answer/resume, audit evidence and the honest real-versus-simulated statement. Compress P01 and P03 into a brief supporting shot; the custom input form can be demonstrated live at judging.
